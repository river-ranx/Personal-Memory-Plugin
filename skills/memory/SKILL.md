# memory — 你的长期记忆

这台电脑上有一份记忆（`~/.memory/memory.db`），Claude Code、Codex、Antigravity 共用：你记下的，
下一个会话里的你、别的 agent 都查得到。**查不查、记什么，都由你判断**——没有程序替你决定。
每轮结束前会有一条 `[Memory]` 提醒让你回顾一下；它只是提醒，该不该记、确认哪条，仍然由你判断，没有就直接结束。

`memory` 不在 PATH 上时用完整路径 `{{MEMORY}}`，下文的 `memory` 都指它。
不管是写代码，还是做研究、写作、分析、管理，用法都一样。
记忆只在本机：路径、账号、联系人、电话想记就记，不会被拦，也不会被改写。
命令本身出错（比如数据库打不开）：照常干活，不要反复重试，也不要改用别的方式记。

## 速查

```sh
memory search 报销 流程 OA              # 查：几个具体的词，中英文都行
memory add "一句话" --kind rule         # 记；--title、--keywords a,b,c、--supersedes 12 可选
memory add - --kind practice <<'TEXT'   # 正文长、带引号或反引号时，从标准输入读
多行正文
TEXT
memory confirm 12                       # 用到了、没发现问题
memory show 12 | list | archive 12 | delete 12
```

**不确定怎么用，先看帮助，不要猜参数**：`memory --help` 是总览，`memory add --help` 是一条命令的全部
（参数、会被拒的情形、每种答复的含义、示例）。参数打错会报错并告诉你这条命令能用什么，照提示改。
id 是数字，写 `12` 或 `#12`；任何命令加 `--json` 得到 JSON。

## 什么时候查

**动手之前先问：这件事，以前有人处理过、定过、走过弯路吗？** 有可能，就查。

- 开始一个任务、话题换了的时候，用任务里的关键词查一次。
- 碰到某个人名、机构、概念、文献、文件、报错或命令，或者用户说「上次那个」「之前说过」的时候。
- 要下结论、做决定、或给建议之前：看有没有已经定下的规则、决策或口径。推翻一个定过的决定之前，先弄清当时为什么这么定。
- 一次查询可以带两个主题的词。没结果就换个说法（同义词、英文名、别称、模块名、更少的词）再查一次，还没有就算了。

## 怎么读结果

每条是一个**头部行**加正文，条与条之间空一行：

```
#12 · preference · 引用格式 · written 3d ago (2026-11-19) · verified
论文引用一律用 GB/T 7714 著者-出版年制；导师说过不要脚注。
```

**先读头部，它决定你怎么对待正文。** 头部是 `#id · 类型 · [标题] · 写入时间`，后面只在**有异常时**才多出内容：

| 头部里 | 意思 | 你该怎么做 |
|---|---|---|
| `rule` | 必须遵守的做法 | 照做——前提是它写下时的情况仍然成立 |
| `decision` | 做过的选择和原因 | 先了解原因，不要轻易推翻 |
| `preference` | 用户的习惯和口味 | 照此调整做法 |
| `practice` | 可复用的做法 | 参考步骤 |
| `fact` | 写下时是什么样 | 可能过时：看写入时间，久了先核实 |
| `may be out of date` | 90 天以前写的 fact | 当它是线索，先核实再用 |
| `verified` | 在几个不同的日子核对过 | 更可信，但不是保证 |
| `contradicted 2x` | 被反驳过 | 先核实，不要直接信 |
| `unused for 90+ days` | 三个月没人用到 | 多核实一下 |
| 一个目录路径 | 来自别的项目 | 想想适不适用于当前项目 |
| `superseded by #13` / `archived` | 只在 list / show 里出现 | 以新的为准 |

## 怎么采纳：记忆是线索，不是事实

**记忆会错**：写下时就记错了、已经过时了、只适用于另一个项目或另一种情形，或者被你读偏了。
所以它是**线索**，不是证据——有选择地用，别照单全收：

1. **先读头部**：多老、什么类型、有没有 `verified` / `contradicted`、是不是别的目录的。
2. **判断它适不适用**这个任务、这个项目。不适用就不用，不必解释。
3. **便宜就核实**：正文里提到的文献、数据、文件、命令，翻一下原文、打开看一眼、跑一下 `--help`，比相信记忆便宜得多。
   **难撤销的事**（删除、发布、对外发出邮件或报告、改别人共用的东西）不要只凭一条记忆去做：先核实，核实不了就问用户。
4. **信任顺序：用户现在说的 > 你现在亲眼看到的（原文、数据、文件、命令输出）> 记忆。**
   `rule`、`decision` 也一样：它们只在写下时的情况还成立时才管用。
5. **记忆和用户现在说的、或你看到的现状不一致**：以后者为准，**说出这个冲突**；真要在两者间取舍而你拿不准，就问用户。
   然后**修正那条记忆**（见「用过之后」）——放着不管，下一个会话还会被它误导。
6. **转述给用户时说明来源**：「我之前的记录里写着……」，别当成你刚验证过的事实。

## 什么时候记

**由你判断，没有任何程序替你决定**：每轮结束的提醒每次都一样，不看用户说了什么，也不看关键词。
边做事边问自己：**换一个新会话，我会希望自己一开始就知道这件事吗？** 会，就记。

- **用户明确要你记住的，一定记**：「记住」「以后都这样」「从现在起」「我决定」「别再…」。
- **用户没说也该记**：被用户纠正过的做法、用户反复强调的偏好、定下的结论和决策（连同理由）、
  概念和口径的界定、资料来源可不可靠及出处、试过不行的思路及原因、人和组织的背景与约定。
- 做完一段较多的工作、任务结束时，回顾一遍有没有值得记的；没有就不记，不用凑数。

## 写成什么样

**写给一个什么都不知道的下一个会话**：他看不到今天的对话，只看得到这一条。

- **一条只写一件事，一句话，最多 1000 字，说清做什么、在哪、为什么。** 带上原因：「城镇化率用常住口径」
  不如「城镇化率用常住口径，因为 2018 年以前的户籍口径和之后不可比」——知道原因，以后才知道什么时候可以例外。
- **自己能读懂**：不写「上面那个」「刚才的方案」；不写「昨天」「最近」（结果会自带写入时间）；写清是哪个课题、
  哪份文件、哪个人、哪个口径、哪个仓库。
- **没确认的猜测不当事实记**：还不确定，就别记，或者在正文里写明「未验证」。
- **关键词是以后找到它的入口**：想想以后的你会拿什么词搜——同义词、英文名、别称、缩写（`ci`、`oa` 都行）。
  `--keywords 城镇化率,口径,统计年鉴`。
- **类型**（`--kind`，不写就是 `fact`）：必须照做的写 `rule`，做过的选择写 `decision`，用户的口味写 `preference`，
  可复用的做法写 `practice`。

```sh
memory add "城镇化率一律用常住口径，因为统计年鉴 2018 年以前的户籍口径和之后不可比" --kind decision --keywords 城镇化率,口径,统计年鉴
memory add "季度复盘材料先给王总过目再发全员，她不喜欢在会上第一次看到数字" --kind preference --keywords 复盘,汇报,王总
memory add "发版只走 release 分支，因为 main 不触发签名流水线" --kind rule --keywords 发版,release,签名
```

## 不记

- **流水账**：今天做了什么、进展到哪、稿子已发给谁、哪章写完了、会开完了、部署完成、某个 MR 已合并——
  邮件、文档、git、流水线里都有。
- **原文、文件、代码、git 里随时查得到的内容本身**：再记一份只是多一份会过期的副本（它在哪、为什么重要，可以记）。
- **只对眼前这件事有效的**：这次会话一结束就没用了。
- **一两个词的标签**（「报销」「release」）：说明不了任何事，会被拒（中文大约连续 4 个字以上才够）。

**以上这些，命令都不会替你拦**（`memory add` 只拦太短的和重复的），全靠你判断。分不清时问自己：**这条说的是发生了什么，还是学到了什么？**
只有前者就不记；夹着教训就只记教训——「问卷已发给全体中层，回收率只有 40%」不记，「问卷要提前跟中层打招呼，
不然回收率只有四成左右」记。规则、决策、偏好、做法可以引用具体的日期、文件、pipeline、commit。

写完看答复：

- `Stored #12.`：存好了。
- `Not stored: already remembered as #id. …`：已经有一条几乎一样的，提示里有一条现成的命令，后面列出那条记忆。你的更新、更准，
  就按提示加 `--supersedes #id` 再写一次；只是重复就放弃。
- `Not stored: refused …` / `invalid memory …`：太短、太长、`--kind` 写错……照提示改，或者放弃。

## 用过之后：让记忆越来越准

用了某条记忆、没发现问题：`memory confirm 12`。你核对过它确实对：`--outcome verified`。这些反馈决定哪些记忆排前面
（同一条、同一种结果，一天只算一次，不用重复）。

**发现某条记忆不对了——文件改名了、做法变了、决定被推翻了——不要放着不管：**

```sh
memory add "访谈稿统一由课题组自己转录，不再外包" --supersedes 12   # 知道现在是什么样：写新的，旧的从此不再被查到
memory confirm 12 --outcome contradicted --note "…"   # 只知道它不对了
```

取代时只写新的正文就行，旧的类型、标题、关键词会继承；新的那条被删除或归档，旧的会重新可用。

排序：标题和关键词里的命中比正文重；这个项目（当前目录、它的上级和子目录）的排在前面，别的项目的照样返回；
被你确认用过、核对过的排前，被反驳的、很久没用到的往后；被新记忆取代的、已归档的不返回。
